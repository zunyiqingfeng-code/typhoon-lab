# 部署方案对比与就绪清单

本文只到"可以动手"为止。凡涉及花钱、注册账号、绑域名、ICP 备案的，都停在这里等拍板，不擅自执行。

## 已就绪的部分（不花钱、已完成）

- 代码与数据仓库：GitHub 私有仓 `typhoon-lab`，全量归档已推送，作为异地备份
- 抓取调度：`.github/workflows/fetch.yml` 每小时抓取，抓后重建主索引、跨年评分、
  跑健康检查（台风数/轨迹点骤降即红灯，GitHub 自动邮件告警）
- 前端：纯静态三页（实时态势图 / 复盘台 / 27 年总榜），只读 JSON，无后端、无鉴权面，
  地图库本地 vendor，零外网依赖
- 也就是说：托管层只需要把这个目录当静态站分发即可，不需要服务器

## 需要你拍板的（花钱 / 账号 / 备案）

### 决策一：托管在哪

两套方案，按你最看重的维度取舍。

方案 A — 腾讯云 EdgeOne Pages 或 COS + CDN
- 境内可达性：好。这是选它的唯一也是决定性理由——面向国内用户不卡不墙
- 成本：EdgeOne Pages 有免费额度，超出按量；COS+CDN 存储+流量按量，台风季流量大时有费用，淡季近乎零
- 维护量：中。需要腾讯云账号、绑定仓库或配置对象存储上传、CDN 刷新
- 备案：绑自有域名走境内 CDN 必须 ICP 备案，见决策二

方案 B — GitHub Pages 或 Cloudflare Pages
- 境内可达性：不稳。大陆访问 GitHub Pages / Cloudflare 时通时不通，只适合当镜像或给技术受众看
- 成本：免费
- 维护量：低。仓库开 Pages 开关即可，Actions 推数据自动更新
- 备案：用平台默认域名不需要备案

建议：主站走 A（境内可达是这个项目的命门），B 作免费镜像并行。但 A 要账号和可能的费用，等你定。

### 决策二：要不要自有域名 + ICP 备案

- 不要：用托管平台的默认二级域名，零成本、零备案，明天就能上
- 要：自有域名需在境内 CDN 前完成 ICP 备案，周期通常一到三周，需要主体信息。这是"长期运营"绕不开的一步，建议早备但由你启动

### 决策三：仓库是否转公开

现在是私有仓（当备份）。若走 GitHub Pages 或希望公开 git 历史（文章素材），需转公开。转公开等于对外发布，属你的决定，我不擅自改。

## 一个技术风险（非花钱，但需验证）

Actions 跑在境外 runner。zjwater / nmc 是境内政府站，境外 runner 能否稳定连通未在真实 Actions 环境验证过（本机是直连验证的）。若境外 runner 被源站限流或封禁导致持续红灯，退路已写在 workflow 尾注：

- 退路 A：自己机器挂 crontab 跑同一脚本再 push（境内出口，最稳，但要一台常开的机器）
- 退路 B：腾讯云函数（境内出口）+ 定时触发器，把数据写回仓库或 COS

这个只有真跑起来才知道，属决策一落地后的第一个待观察项。

## 落地顺序建议

1. 你定决策一、二、三
2. 若 A：开腾讯云账号 → 配置静态托管 → 接 GitHub 仓库或配置数据同步
3. 观察 Actions 境外连通性，不稳则切退路 A/B
4. 若要域名：并行启动 ICP 备案
5. B 作镜像可随手开，零成本

到这一步之前，本地 `python3 -m http.server 8000` 打开 `/web/` 就是完整的预览环境。
